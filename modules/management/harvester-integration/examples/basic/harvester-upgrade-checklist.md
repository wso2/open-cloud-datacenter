# Harvester Upgrade Checklist

> **Status** must be one of: `Pending`, `Completed`, `Validated`.

| Phase | Step ID | Component / Area | Task Description | Action / Command | Status | Notes / Remediation |
|---|---|---|---|---|---|---|
| Preflight | PRE-01 | VM Management | Manage non-migratable VMs behavior based on restoreVM setting. | `kubectl get settings.harvesterhci.io upgrade-config -o yaml` | Pending | Non-migratable VMs will experience downtime. |
| Preflight | PRE-02 | Storage / Backup | Back up all critical virtual machines. | N/A (Perform VM backups via preferred method) | Pending | Required for data recovery in case of unexpected host or storage failures. |
| Preflight | PRE-03 | Cluster Admin | Freeze cluster operations (no new VMs, image uploads, or network configs). | N/A (Communicate freeze to team) | Pending | Prevents resource race conditions and cluster state mismatches. |
| Preflight | PRE-04 | Hardware | Verify hardware meets preferred requirements. | N/A (Check cluster specs) | Pending | Upgrade may fail if intermediate resources are exhausted. |
| Preflight | PRE-05 | Storage / Partition | Verify at least 30 GiB of free system partition space (/usr/local/) on each node. | `df -h /usr/local/` (Run on each host) | Pending | Upgrade will be denied if any node has less than 30 GiB free space. |
| Preflight | PRE-06 | System / Pre-check | Run the official pre-check script on a Harvester control-plane node. | Run upgrade-helpers pre-check script | Pending | Take action on any failed checks before initiating the upgrade process. Known failure causes: managed chart drift (see PRE-11) and single-replica volumes (see PRE-12). |
| Preflight | PRE-07 | Security / PSA | Adjust Pod Security Admission (PSA) policies to allow privileged upgrade pods. | Update PSA for harvester-system and cattle-system namespaces | Pending | Required only if Pod Security Admission is enabled. |
| Preflight | PRE-08 | System / Time | Ensure all nodes' times are in sync using an NTP server. | `sudo -i`<br>`vim /etc/systemd/timesyncd.conf`<br>`timedatectl set-ntp true`<br>`sudo timedatectl status` | Pending | Manually configure NTP on each node if not configured during installation. |
| Preflight | PRE-09 | Network / NICs | Review vendor KB for NICs connected to a PCI bridge. | N/A (Review hardware documentation) | Pending | NICs might be renamed after an upgrade reboot sequence. |
| Preflight | PRE-10 | Storage / RWX | Verify the Longhorn RWX storage network setting is applied. | `kubectl get settings.longhorn.io storage-network storage-network-for-rwx-volume-enabled -n longhorn-system` (< 1.8.0)<br>`kubectl get settings.longhorn.io storage-network endpoint-network-for-rwx-volume -n longhorn-system` (>= 1.8.0)<br>`kubectl get pod -n longhorn-system -l app=longhorn-csi-plugin -o jsonpath='{range .items[*]}{.metadata.name}{"\n"}{.metadata.annotations.k8s\.v1\.cni\.cncf\.io/network-status}{"\n\n"}{end}'` | Pending | If `applied=false` and the csi-plugin pods have no interface on the storage network, the `importer-prime-` pod's RWX volume will fail to mount (see #516). From Harvester 1.8.0 the setting is renamed to `endpoint-network-for-rwx-volume`. |
| Preflight | PRE-11 | System / Managed Chart | Fix managed chart drift causing pre-check failure (Longhorn replica count mismatch). | `kubectl -n fleet-local patch managedcharts.management.cattle.io harvester --type=merge -p '{"spec":{"values":{"longhorn":{"persistence":{"defaultClassReplicaCount":2}}}}}'`<br>`kubectl -n cattle-fleet-local-system delete pod -l app=fleet-agent` | Pending | Re-run the pre-check script after patching to confirm the drift is resolved. |
| Preflight | PRE-12 | Storage / Longhorn | Increase replica count for single-replica volumes flagged by the pre-check script. | `./check.sh \| awk '/single-replica volume in running state/ {print $2}' \| xargs -I {} kubectl patch lhv {} -n longhorn-system --type=merge -p '{"spec":{"numberOfReplicas":2}}'` | Pending | Recommended action when the pre-check script finds single-replica volumes in a running state. |
| Preflight | PRE-13 | VM Management / Backup | Suspend virtual machine backup schedules. | N/A (Pause/disable scheduled VM backup jobs) | Pending | Prevents scheduled backup jobs from conflicting with in-flight VM migrations and node reboots during the upgrade. |
| Announcement | ANN-01 | Communication | Send email to downstream teams informing there will be an upgrade. | N/A (Send notification email) | Pending | Gives affected teams advance notice of the maintenance window. |
| Preparation | PRP-01 | Planning | Determine upgrade method based on host internet access. | `curl -I https://releases.rancher.com/harvester/v1.8.2/harvester-v1.8.2-amd64.iso` | Pending | Reachable → use Method 1 (Internet-Connected), skip PRP-02/PRP-03, go to EXE-01. Not reachable → use Method 2 (Air-Gapped), continue with PRP-02/PRP-03. |
| Preparation | PRP-02 | Image Management | Download Harvester ISO and host on an internal HTTP server. | Download from GitHub Releases, save to HTTP server (e.g., http://10.10.0.1/harvester.iso, or `python3 -m http.server 80`) | Pending | Required only for Method 2 (Air-Gapped) upgrades. |
| Preparation | PRP-03 | Version Manifest | Download and modify version.yaml with local isoURL and host it. | Update isoURL in version.yaml and host (e.g., http://10.10.0.1/version.yaml) | Pending | Required only for Method 2 (Air-Gapped) upgrades, to trigger the upgrade via custom resource. |
| Execution | EXE-01 | CLI Upgrade (Method 1) | Start upgrade via CLI by applying the upstream manifest directly. | `sudo -i`<br>`kubectl create -f https://releases.rancher.com/harvester/v1.8.2/version.yaml` | Pending | Internet-Connected method; no local ISO hosting required. Skip Preparation phase (PRP-02/PRP-03). |
| Execution | EXE-02 | CLI Upgrade (Method 2) | Start upgrade via CLI by creating the version custom resource from the local manifest. | `sudo -i`<br>`kubectl create -f http://10.10.0.1/version.yaml` | Pending | Air-Gapped method. Also use this method if the UI upgrade button is not visible initially. |
| Troubleshooting | TRB-01 | Image Download | Verify image download and conversion to raw disk image. | Check logs of importer-prime- pod in harvester-system namespace. | Pending | Look for transfer/scratch and convert phase errors. |
| Troubleshooting | TRB-02 | Local Repository | Verify local repository creation for image preloading. | `kubectl logs -f upgrade-repo-... -n harvester-system` | Pending | Ensures Nginx is successfully serving the ISO to nodes. |
| Troubleshooting | TRB-03 | System Service | Verify upgrade of control plane, management layer, and system charts. | Check logs of hvst-upgrade-...-apply-manifests-... pod. | Pending | Crucial step — this stage runs before node upgrades/reboots begin. |
| Troubleshooting | TRB-04 | Node Upgrade | Monitor image preloading, pre-drain, and post-drain sub-stages during node upgrade. | `kubectl logs -f apply-hvst-upgrade-...-prepare-on-node1-...  -n cattle-system`<br>`kubectl get vmim -A`<br>`kubectl get jobs -n harvester-system -l harvesterhci.io/upgradeComponent=node`<br>`kubectl logs -n harvester-system jobs/hvst-upgrade-...-pre-drain-...`<br>`kubectl logs -n harvester-system jobs/hvst-upgrade-...-post-drain-...` | Pending | Pre-drain: the first node migrates all VMs immediately; subsequent nodes wait for Longhorn volume rebuild to finish before VM migration starts. Post-drain: the node's OS image is upgraded and the node is rebooted. If a VM fails to migrate during pre-drain, see ISS-04 as a last resort. |
| Completion | CMP-01 | Upgrade Verification | Verify completion of Harvester upgrade. | `kubectl get nodes` | Pending | Check if the Kubernetes version has been upgraded on all nodes in the Harvester cluster and that all nodes are Ready. |
| Completion | CMP-02 | Delete upgrade CR | Delete the upgrade after it is completed. | `kubectl get upgrade.harvesterhci.io -n harvester-system -l harvesterhci.io/latestUpgrade=true`<br>`kubectl delete upgrade.harvesterhci.io/<upgrade-name> -n harvester-system` | Pending | |
| Completion | CMP-03 | Check etcd size | Use etcdctl to verify etcd has not exceeded its quota. | https://jmcglock.substack.com/p/recovering-a-harvester-cluster-from | Pending | |
| Completion | CMP-04 | Storage / Longhorn | Check all Longhorn volumes. | Using the Longhorn UI, check if all volumes have recovered. | Pending | Confirm every volume shows Robustness = Healthy and replica rebuilds have finished before closing out the upgrade. |
| Completion | CMP-05 | VM Management | Check all VMs are running. | `kubectl get vmi -A` (or verify via Harvester/Rancher UI) | Pending | Confirm every VM that was running before the upgrade is in Running state after upgrade. |
| Issues | ISS-01 | Storage / RWX | RWX volume of importer-prime pod not mounting. | `kubectl get settings.longhorn.io storage-network storage-network-for-rwx-volume-enabled -n longhorn-system` (< 1.8.0)<br>`kubectl get settings.longhorn.io storage-network endpoint-network-for-rwx-volume -n longhorn-system` (>= 1.8.0)<br>`kubectl get pod -n longhorn-system -l app=longhorn-csi-plugin -o jsonpath='{range .items[*]}{.metadata.name}{"\n"}{.metadata.annotations.k8s\.v1\.cni\.cncf\.io/network-status}{"\n\n"}{end}'` | Pending | Caused by the storage network setting for RWX volumes not being applied (`applied=false`, no CSI interface on storage network). See [#516](https://github.com/wso2-enterprise/wso2-datacenter-project/issues/516). Setting renamed to `endpoint-network-for-rwx-volume` from Harvester 1.8.0. |
| Issues | ISS-02 | System / Managed Chart | Pre-check script fails due to managed chart drift. | `kubectl -n fleet-local patch managedcharts.management.cattle.io harvester --type=merge -p '{"spec":{"values":{"longhorn":{"persistence":{"defaultClassReplicaCount":2}}}}}'`<br>`kubectl -n cattle-fleet-local-system delete pod -l app=fleet-agent` | Pending | Caused by a replica count mismatch on the Longhorn storage class due to chart drift. Re-run pre-check after patching. |
| Issues | ISS-03 | Storage / Longhorn | Pre-check script fails due to single-replica volumes. | `./check.sh \| awk '/single-replica volume in running state/ {print $2}' \| xargs -I {} kubectl patch lhv {} -n longhorn-system --type=merge -p '{"spec":{"numberOfReplicas":2}}'` | Pending | Recommended action: increase replica count of single-replica volumes in running state to 2. |
| Issues | ISS-04 | VM Migration | VM fails to migrate in the pre-drain stage. | `kubectl apply -f -` with a `MigrationPolicy` (`allowAutoConverge: true`) scoped to the VM via `virtualMachineInstanceSelector` | Pending | Only apply if migration fails to converge (e.g. large/busy VMs). Throttles the VM's vCPU to slow its dirty page rate — the VM and its application will experience degraded CPU performance until migration completes. |
